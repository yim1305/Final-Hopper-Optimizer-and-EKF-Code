# Animation — Hopper1 flight videos

The scripts in this folder render animations of the saved 8-A2200 reference flight (the `a2200_08` case from Astro). Every plotted position and thrust sample comes from the saved optimizer trajectory; nothing is re-solved. The terrain shown is the same 30 m digital elevation model that Astro uses. The sun direction used for the terrain shading is illustrative only, not the mission Sun.

## The two scripts

| Script | What it renders |
|---|---|
| `animate_hop.py` | A fixed-camera MP4 of the whole round trip (outbound and return) with close-ups at launch and at landing. Playback is time-compressed so that the whole flight fills 48 s of video. The vertical rise, braking, observation and terminal phases each get a fixed amount of screen time per hop (3, 3, 4 and 4 s), and the other phases share the rest at one rate. A 2 s hold follows the touchdown. |
| `animate_phases.py` | A video of the outbound hop only, with a moving camera that zooms in at launch, zooms out for the coast and zooms in again at the landing site. Only the name of the current phase is shown. It has the same look as `animate_hop.py` and imports that script for its loaders, colors and terrain helpers, so keep the two files together. |

Both write 1920 x 1080 video at 30 frames per second using `imageio-ffmpeg` (H.264, listed in `requirements.txt`).

## Inputs

The scripts only read from Astro; they never change anything there.

- The saved flight in `Astro/results/a2200_08/`: `trajectory.npz` and `phases.csv`. These are generated by `Astro/scripts/run_case.py a2200_08` (see the [repository README](../README.md)). The repository stores only the optimizer restart arrays, so run that command first.
- Astro's `mission` package (the case parameters and the DEM terrain model), and the terrain files in `Astro/data/`.

## Outputs

All output is generated locally under `Animation/results/` and is not stored in the repository. The folder is created when a script runs.

| Script | Output folder | Files |
|---|---|---|
| `animate_hop.py` | `Animation/results/a2200_08/` | `hop_animation.mp4`, `poster.png` (last frame), `playback.json` (the time-compression schedule). With `--preview`: `preview_<phase>.png` stills for each phase (instead of the video), plus `poster.png` and `playback.json`. |
| `animate_phases.py` | `Animation/results/a2200_08_phases/` | `hop_phases.mp4` and `poster.png`. With `--preview`: a few `preview_<frame number>.png` stills instead (no video, no poster). |

## Requirements

The packages in `requirements.txt`, notably `matplotlib` for the rendering and `imageio-ffmpeg` for writing the MP4 (it supplies its own ffmpeg binary). Previews (`--preview`) skip the video encoder.

## Commands

**Run from the repository root, after `Astro/scripts/run_case.py a2200_08` has been run.** The animation scripts cannot run from a fresh clone alone: a fresh clone has only the restart arrays, and both scripts read the generated `Astro/results/a2200_08/trajectory.npz` and `phases.csv`. They write only to `Animation/results/`, which they create:

```powershell
# Whole round trip: full MP4
.\.venv\Scripts\python.exe -B Animation/animate_hop.py

# Whole round trip: PNG stills only (quick check, no video)
.\.venv\Scripts\python.exe -B Animation/animate_hop.py --preview

# Outbound hop with the moving camera: full MP4
.\.venv\Scripts\python.exe -B Animation/animate_phases.py

# Outbound hop with the moving camera: PNG stills only
.\.venv\Scripts\python.exe -B Animation/animate_phases.py --preview
```

The only command-line option of either script is `--preview`. Playback timing, resolution, frame rate and camera settings are constants at the top of each script.
